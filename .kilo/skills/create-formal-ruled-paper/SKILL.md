# Skill: Create Formal Ruled Paper

## Purpose

Generate A4 ruled writing paper with Mathayom header and student demographics — one header page (with ruled lines) followed by a blank ruled page, ready for 2-sided duplex printing. Same format as the formative ruled paper, **without** the booklet interleaving.

**Output:** `PDF/FORMAL-RULED/{CLASS}-formal-ruled.pdf` (merged class PDF) + individual PDFs in temp

## When to Use

Use this skill when:
- A teacher needs formal ruled writing paper for tests or exams
- Duplex A4 output is needed (not A5 booklets)
- Student demographics (name, class, ID) should appear on the header page
- Blank ruled paper only is needed via `blank: true` mode

Do NOT use this skill when:
- A5 booklet production is needed (use `create-formative-ruled-paper` instead)
- The output needs to be interleaved for mechanical slicing

**Trigger:** `/create-formal-ruled-paper` command or when the user asks to generate ruled writing paper for a class.

## Pipeline

```
Markdown (YAML frontmatter only)
    │
    ▼
pandoc --lua-filter=scripts/ruled-paper.lua -t typst
    │
    ▼
Typst source (generated by Lua filter, never hand-written)
    │
    ▼
typst compile --root "." --font-path <roboto> → PDF per student
    │
    ▼
Python concatenates all student PDFs sequentially →
  PDF/FORMAL-RULED/{CLASS}-formal-ruled.pdf
```

The Lua filter (`scripts/ruled-paper.lua`) is shared with the formative ruled-paper skill. No changes needed there.

## Input

Same YAML frontmatter as formative ruled paper:

```markdown
---
class: M3-5A
student_id: "29508"
name: "Satang"
---
```

Or blank mode:
```markdown
---
blank: true
---
```

**YAML fields:**
| Field | Required | Description |
|-------|----------|-------------|
| `class` | Yes* | Class section (e.g. M3-5A) |
| `student_id` | Yes* | Student ID number |
| `name` | Yes* | Student name |
| `blank` | No | If `true`: ruled lines full-page, no header/demographics |

\*Not required when `blank: true`.

## Workflow

### Step 1 — Write Markdown

Only YAML frontmatter. No body content. No Typst. No HTML.

### Step 2 — Run Python Batch Script

```powershell
# Full class (recommended):
python scripts/gen_formal_ruled.py --class M3-5A

# Blank ruled paper only (no demographics):
python scripts/gen_formal_ruled.py --blank
```

### Step 3 — Verify Output

Check `PDF/FORMAL-RULED/{CLASS}-formal-ruled.pdf`:
- Page 1: Mathayom header + student name/class/ID + ruled lines
- Page 2: Blank ruled lines only
- Print 2-sided (duplex) on A4 — each physical sheet = header side + blank ruled side

## Examples

### Example 1: Full class exam paper

**Request:** "Generate formal ruled paper for M3-5A"

**Action taken:** Run `python scripts/gen_formal_ruled.py --class M3-5A`. The script queries Supabase for the classlist, generates individual Markdown files, pipes through Pandoc + Lua filter → Typst → PDF, then concatenates all student PDFs sequentially.

**Output:** `PDF/FORMAL-RULED/M3-5A-formal-ruled.pdf`

### Example 2: Blank ruled paper

**Request:** "I need blank ruled paper with no header"

**Action taken:** Run `python scripts/gen_formal_ruled.py --blank`. Produces a single-page PDF with ruled lines only, no school branding.

**Output:** `PDF/FORMAL-RULED/blank-ruled.pdf`

### Example 3: Debug one student

**Request:** "Test with a single student before batch"

**Action taken:** Write a Markdown file with YAML frontmatter for one student, run Pandoc with `--lua-filter=scripts/ruled-paper.lua` to produce a `.typ` file, then `typst compile` to PDF.

## Key Differences from Formative Ruled Paper

| Aspect | Formative | Formal |
|--------|-----------|--------|
| Output | A5 booklet (interleaved pairs + blanks) | A4 duplex (straight concatenation) |
| Page order | St1, St2, blank, blank, St3, St4... | St1-p1, St1-p2, St2-p1, St2-p2... |
| Slicing | Mechanical slice A4 → A5 | No slicing — print direct on A4 |
| Use case | Booklet production for students | General writing paper, tests, exams |

## Error Handling

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `--root "."` error | Typst cannot resolve `/templates/` paths | Add `--root "."` to `typst compile` command |
| Font not found | Font path missing or wrong | Verify TinyTeX Roboto OTF directory in `--font-path` |
| Underscore in output | `_` in values interpreted as Typst emphasis | Use `-` instead of `_` as placeholder |
| Supabase query fails | Linked project not configured | Verify `--project-ref hdpwaqprrgnndkgzmnan` |

## Hard-Won Lessons

### Fill remaining space, don't count lines
```typst
#block(height: 1fr, layout(size => {
  let n = int(size.height / ls)
  for i in range(n) {
    v(ls / 2)
    line(length: 100%, stroke: 0.4pt + black)
    v(ls / 2)
  }
}))
```

### Tool path resolution on Windows
Winget-installed pandoc/typst may not be on system PATH. The script resolves full paths.

### Supabase JSON output avoids encoding issues
Use `supabase db query --linked -o json`.

### Nil metadata handling in Lua filters
Always guard against nil metadata values.

## Known Constraints

- `--root "."` is required for `typst compile` to resolve `/templates/` paths.
- Font path must point to TinyTeX Roboto OTF directory.
- `_` in values is forbidden — use `-` as placeholder.
- The classlist query uses the linked Supabase project (`--project-ref hdpwaqprrgnndkgzmnan`).
