# Creative Techniques for Lesson Design

**Read this BEFORE picking a lesson plan shape.** The shape is a scaffold — the objective and creative approach should choose the shape, not the other way around.

---

## Lead with these questions

Before writing a single stage, ask:

1. **What's the real problem?** — Is there a known student difficulty this lesson solves? Lead with the problem, not the topic.

2. **What's the ONE insight?** — If students remember nothing else, what should stick? Not a language rule — a realisation.

3. **Can we use comparative input?** — Two versions of the same thing side by side forces noticing without explicit instruction.

4. **Can the task be persona-based?** — "You're not you — you're a food critic / a weather reporter / Cherry Valance." Depersonalises performance.

5. **Can we start with feedback?** — Return actual student work at the beginning. Let them see their own patterns first.

6. **Can the practice stage be dramatic?** — Table reads, role-plays, scenes, debates, press conferences.

7. **What would McKinsey ask?** — Define the problem statement. Gather data. Test hypotheses. Present a recommendation.

---

## Technique Library

### Problem-first opening
Start by showing student work or returned feedback. Let students diagnose the problem themselves. The lesson is the solution.

*Used in:* M3-LESSON01-DRAMA (returned speaking test feedback surfaced flat intonation, fear, hesitation before any input)

### Comparative input (noticing gap)
Present two versions of the same content — one weaker, one stronger — and ask: "What do you notice?" Students spot the gap without being told what it is.

*Used in:* M3-LESSON01-DRAMA (Breaking Bad table read vs. filmed scene — same dialogue, different delivery)

### Persona-based speaking
Frame the productive task as: "You're not [student name]. You're [expert / character / role]." Depersonalises performance, lowers the affective filter.

*Used in:* M3-LESSON01-DRAMA (students read as Dally / Cherry / Johnny, not as themselves)

### Drama / table-read format
Students perform from a script seated at a table, voices only, no blocking. Removes physical performance anxiety while keeping the voice work. Can be followed by a full performance for comparison.

*Used in:* M3-LESSON01-DRAMA (Chapter 2 read-aloud as characters)

### McKinsey-style problem solving
1. Define the problem: "How can we show Triam Udom / MUIC admissions that we have what they need?"
2. Gather data: examine model statements, identify what makes them persuasive
3. Test hypotheses: draft and peer-test own statements
4. Present recommendation: final polished version with rationale

*Works for:* relative clauses, persuasive language, hedging, formal register, discourse markers

### Grammar through a problem lens
Instead of "Today we're learning relative clauses," frame it as: "How can you pack more information into one sentence?"

*Works for:* relative clauses, compound adjectives, passive voice, conditionals, reported speech

## McKinsey Approach for ESL

The McKinsey problem-solving method adapts naturally to language teaching. It replaces "learn this rule" with "solve this problem" and gives students a structured way to test their own hypotheses about language.

### The 7-Step Framework

| Step | In consulting | In ESL |
|------|---------------|--------|
| **1. Define the problem** | "How do we increase profit by 15%?" | "How can you show Triam Udom / MUIC that you have what they need?" |
| **2. Structure it (MECE)** | Break profit into revenue streams and costs | Break speaking into content / language / delivery |
| **3. Form a hypothesis** | "I think lowering price will drive volume" | "I think a personal story makes me more memorable" |
| **4. Test the hypothesis** | Run a pilot | Record yourself with and without the technique |
| **5. Analyze the data** | Did revenue increase? | Did fluency improve? Did hesitation decrease? |
| **6. Synthesise findings** | "Price cuts didn't drive enough volume" | "Stories work, but only when connected to the skill" |
| **7. Recommend** | "Focus on product bundling instead" | "Lead with a personal anecdote, then state your qualification" |

### MECE for Language Problems

MECE (Mutually Exclusive, Collectively Exhaustive) means breaking a problem into parts that don't overlap but cover everything:

```
Speaking performance
├── Content (what you say)
│   ├── Ideas
│   └── Organisation
├── Language (how you say it)
│   ├── Vocabulary range
│   ├── Grammar accuracy
│   └── Pronunciation
└── Delivery (the performance)
    ├── Pace
    ├── Volume
    ├── Intonation
    └── Confidence ← the drama lessons focus here
```

This lets the teacher and students agree: "We're working on DELIVERY, not content or language." The problem is bounded and manageable.

### Three ESL Applications

**1. Grammar through a problem lens**
Instead of "Today we're learning relative clauses":
> *"How can you pack more information into one sentence without making it confusing?"*
> → Hypothesis: "I think adding 'who' and 'which' after the noun works"
> → Test: Write two versions, compare clarity
> → Synthesise: "Relative clauses work best for describing people"

**2. University interview preparation**
> *"How can we show Triam Udom / MUIC admissions that we have what they need?"*
> → Structure: content, delivery, confidence, evidence
> → Hypothesis: "I think starting with a personal story makes me more memorable"
> → Test: Record with and without a story
> → Synthesise: "Stories create connection, but must link to the skill being demonstrated"
> → Recommend: "Open with a 30-second anecdote, then transition to qualifications"

**3. Drama / performance (this lesson series)**
> *"Why does your voice sound flat when you're nervous, and how do actors fix this?"*
> → Hypothesis: "Actors solve it by becoming someone else"
> → Test: Read as yourself, then read as Dally / Cherry / Johnny
> → Synthesise: "The character frees you from self-consciousness"
> → Recommend: "Before your next speaking test, choose a persona. You're not you — you're the character."

### When to use McKinsey-style

| Use it | Don't use it |
|--------|-------------|
| Speaking tests / exam prep | Simple comprehension checking |
| Persuasive writing | Beginner-level vocabulary drills |
| University applications | Lessons with a clear right/wrong grammar target |
| Debates and presentations | When students lack enough language to form hypotheses |
| Multi-skill synthesis tasks | When the shape already serves the objective perfectly |

---

## When NOT to use creative techniques

- When the shape's standard structure already maps perfectly to the objective
- When the teacher explicitly wants a standard lesson plan
- When the creative approach would add complexity without adding learning value

---

## Integration with the lesson plan skill

The agent should ask the 7 questions above BEFORE consulting the shape list. If two or more techniques apply, use them to select and adapt the shape:

- Problem-first + comparative input → Shape C (Test-Teach-Test) or Shape G (TBL)
- McKinsey-style problem solving (define → hypothesise → test → recommend) → Shape C (Test-Teach-Test)
- Comparative input → Shape E (Receptive Skills) with noticing-not-comprehension post-task
- Persona-based speaking → Shape F (Productive Skills) with persona in the lead-in
- Drama / table-read → Shape F with production as performance

The shape is never the starting point. The objective and the creative approach come first.
