# Skill: create-speaking-grading-sheet

## Purpose

Generate a Pronunciation Grading Sheet as a single A4 PDF with Mathayom header, student demographics, SCORE box, a 5-band × 4-criterion grading rubric, and a Special Observations box that fills remaining page space.

## Pipeline

```
Markdown (YAML + pipe table + fenced divs)
    │  pandoc --template=templates/speaking-grading.typ
    │         --lua-filter=scripts/speaking-grading-sheet.lua
    ▼
Typst source (generated by Pandoc, filtered by Lua)
    │  typst compile
    ▼
PDF (single page)
```

## Architecture

| Layer | File | What it does | Locked? |
|-------|------|-------------|---------|
| **Template** | `templates/speaking-grading.typ` | Page setup, masthead header, demographics (`$class$`, `$student_id$`, `$name$`), body placeholder. Uses Pandoc `$variable$` syntax — Typst never sees raw variable names. | Yes — never edit |
| **Lua filter** | `scripts/speaking-grading-sheet.lua` | Transforms what Markdown can't express: centered bold title, pipe table → Typst `#table()` with gray fills on bands 4/2, centered bold band numerals, SCORE 2-column grid, bordered observations box (`height: 1fr`) | Yes — never edit |
| **Markdown** | Agent-written | YAML frontmatter + `::: {.score}` div + `# Title` + pipe table + `::: {.observations}` div | Yes — agent writes this |
| **Tests** | `tests/test_speaking_grading.py` | Red-green: verifies Markdown structure, Pandoc→Typst→PDF pipeline, PDF content extraction | Yes — run before/after changes |

## Input Markdown Format

```markdown
---
class: M3-4A
student_id: "29508"
name: "Satang"
---

::: {.score}
:::

# Speaking Grading Sheet — Pronunciation

| Band | Intonation | Intelligibility | Sentence and Word Stress | Individual Sounds |
|------|-----------|----------------|------------------------|--------------------|
| 5 | Intonation is natural and appropriate. | Always clear. | Stress is natural and accurate. | Sounds are clear. |
| 4 | Between 5 and 3. | Between 5 and 3. | Between 5 and 3. | Between 5 and 3. |
| 3 | Intonation OK in patches. | Mostly clear. | Stress OK in patches. | Some sounds muddled. |
| 2 | Between 3 and 1. | Between 3 and 1. | Between 3 and 1. | Between 3 and 1. |
| 1 | Intonation defects constant and obvious. | Often unclear or hard to follow. | Stress errors constant and obvious. | Many sounds unclear or distorted. |

::: {.observations}
**Special Observations**
:::
```

**YAML fields:**
| Field | Required | Maps to template |
|-------|----------|------------------|
| `class` | Yes | `$class$` |
| `student_id` | Yes | `$student_id$` |
| `name` | Yes | `$name$` |

**Fenced divs processed by Lua filter:**

| Div class | Transforms to |
|-----------|---------------|
| `::: {.score}` | Narrow 2-column table: gray `SCORE` left, white blank right (for handwriting) |
| `::: {.observations}` | Bordered `#block(height: 1fr)` filling remaining page space |

## What the Lua Filter Does

### Header filter
Catches level-1 headings and wraps them in `#align(center)[*...*]` with `#v(0.5em)` padding above and below.

### Table filter
Replaces the Pandoc pipe table AST with a Typst `#table()`:
- Header row: gray (`luma(220)`) background on all cells
- Bands 4 and 2: gray background rows
- First column (band numerals): bold, centered horizontally and vertically
- Content columns: left-aligned, top-aligned
- Fixed column structure: `auto, 1fr, 1fr, 1fr, 1fr`

### Div filter (`observations`)
Inserts `#v(1em)` spacing then a bordered `#block(height: 1fr)` that fills all remaining vertical space on the page.

### Div filter (`score`)
Generates a 2-column `#table(columns: (6em, 6em))` with gray SCORE cell and white blank cell. Narrow enough for handwriting a number without stretching page width.

## Invocation

```powershell
# Generate one page:
pandoc student.md -t typst --template=templates/speaking-grading.typ \
  --lua-filter=scripts/speaking-grading-sheet.lua -o student.typ
typst compile --root "." \
  --font-path "$env:APPDATA\TinyTeX\texmf-dist\fonts\opentype\google\roboto" \
  student.typ student.pdf

# Run tests:
python -m pytest tests/test_speaking_grading.py -v
```

## Tests

`tests/test_speaking_grading.py` — 3 tests:

| Test | Verifies | Type |
|------|----------|------|
| `test_md_body_contains_expected_elements` | Markdown source has YAML, divs, table headers | Unit (no tools) |
| `test_lua_filter_loads_and_transforms_score_div` | Pandoc + Lua filter → Typst with SCORE, observations, table | Integration |
| `test_full_pipeline_produces_valid_pdf` | PDF exists, non-empty, contains student name, SCORE, Intonation | End-to-end |

**Red-Green TDD is critical.** Before implementing any feature (e.g., a new div class), first add a test that expects it. Then implement until the test passes. After any change, run the full test suite:
```
python -m pytest tests/ -v
```

## Hard-Won Lessons

### 1. Red-Green TDD saved hours
Writing `test_speaking_grading.py` before finalizing the Lua filter caught:
- Pandoc 3.x Table API differences from 2.x (`el.head.rows` ≠ `el.headers`)
- Typst syntax errors (`fill: white` vs `luma(220)`)
- Missing `height: 1fr` support (requires Typst 0.12+)
- Tool PATH issues (pandoc not on subprocess PATH)

Without tests, every iteration required manual PDF inspection. Tests automate it.

### 2. First, run the tests
Before making any change to the pipeline:
```bash
python -m pytest tests/test_speaking_grading.py -v
```
If existing tests fail, the change introduced a regression. Fix before proceeding.

### 3. Template is locked, never edit it
`templates/speaking-grading.typ` is static infrastructure. Pandoc `$variable$` syntax resolves YAML fields before Typst sees them. If you need to change layout, modify the Lua filter, not the template.

The one authority exception: setting `#set par(leading: 0.25em)` before `$body$` for 1.25 line spacing in table descriptors. This was intentional infrastructure setup, not an agent edit.

### 4. Research before guessing
When uncertain about Pandoc's Lua Table API, Typst `1fr` behavior, or template variable syntax, use **Tavily** first. Trial-and-error with Typst compilation is costly (60s per cycle). A 15s Tavily search found the `#block(height: 1fr)` pattern instantly.

### 5. Pandoc 3.x Table AST structure
```
Table → head → rows[1] → cells[]         (header)
     → bodies[1] → [4] or .rows → rows[] (body rows)
```
Each cell has `.content` (list of blocks). Use `pandoc.utils.stringify(cell.content)` for text.

### 6. `#block(height: 1fr)` fills remaining page space
Researched via Tavily → confirmed in Typst docs → implemented in observations box. This replaced a hardcoded `height: 3cm` that never looked right.

### 7. All Typst lives in the Lua filter or template
The Lua filter generates Typst `RawBlock` strings. The template provides `$body$`. Neither is hand-edited by agents writing Markdown. The Markdown body contains only YAML, fenced divs, pipe tables, and headings — no Typst.

### 8. Tool path resolution on Windows
Pandoc 3.10 (winget): `C:\Program Files\Pandoc\pandoc.exe`
Typst (winget): `C:\Users\elwru\...\typst.EXE`
Tests and scripts must use full paths — subprocess does not inherit the refreshed PATH.

## Known Constraints

- Font must be Roboto 14pt (from TinyTeX). Smaller violates the 14pt minimum requirement.
- Pipe table in Markdown must have exactly 5 columns. The Lua filter assumes 5-column structure.
- `height: 1fr` requires Typst 0.12+ (we have 0.14.2).
- `::: {.score}` div must be empty (content is ignored).
- `::: {.observations}` div content is replaced by bordered box — the `**Special Observations**` text is decorative Markdown, not rendered.
- Student metadata from Supabase uses the same format (`-o json` on `supabase db query`).
