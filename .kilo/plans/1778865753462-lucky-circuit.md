# Plan: Systematic Code Review for Lesson Plan Writer 3

## Decisions (confirmed by user)
- **Comprehensive checklist**: all AGENTS.md rules included
- **Integrate with `/git-backup`**: run `/review` as pre-commit gate (in addition to `/lint`)
- **Scope**: uncommitted working-tree changes only (no commit history review)

## Implementation Plan

### 1. Create `.kilo/command/review.md`

A command that performs a systematic review in four phases:

**Phase 1 — Automated Checks**
1. Run `ruff check --fix .` (lint)
2. Run `ruff format .` (format)
3. Run `python -m pytest tests/ -v` (all 56 tests)
4. Stop and report if any of the above fail

**Phase 2 — Uncommitted Changes Audit**
5. `git diff --stat` (files changed summary)
6. If nothing to review: "No uncommitted changes to review" and exit cleanly
7. `git diff` (full diff for analysis)

**Phase 3 — Project-Specific Quality Review**

Check changed files against ALL AGENTS.md rules:

**HTML Slides** (`output/*/slides/index.html`):
- Icon placement: inline left of `<h2>` inside `overflow: hidden` div (not centered block)
- Transition/objective/answer icons: use `slide-icon` + type class pattern
- Auto-animate: sibling `<section data-auto-animate>` pairs only adjacent; no `data-auto-animate` on previous non-matching slide
- Fragment classes: no `highlight-*` (forces `opacity: 1`); use `answer-correct`/`answer-incorrect` custom classes
- Fragment strike: `class="fragment strike"` on td/p with `data-fragment-index` matching
- Answer tables: `<table class="answer-table">` with 3 columns (Statement/Answer/Why?); `wrap` class for long text; right column `white-space: normal`
- Answer table middle column: `data-fragment-index` matching explanation cell
- Step labels: `<p><u><strong>Step N:</strong> description</u></p>` format
- Pedagogical slides: `data-background="#1a6b5a"` + `class="pedagogical"` + `data-background-transition="none"`
- Pedagogical alignment: no negative margin-top; `padding-top: 30px` via CSS rule `.reveal .slides > section.pedagogical { align-self: flex-start; padding-top: 30px; }`
- Lightbulb icons: removed from all answer slides
- Transition icons: `fa-forward` with red `#c0392b` background; `transition-icon` class
- One step per slide: each strategy step on its own `<section>`
- Header on first slide only of strategy blocks; remaining show only step label
- Original question in yellow (`style="color:#ffdd00;"`) on first and last strategy slides
- No `data-auto-animate` on Step 1 (only on Step 2a/2b pair)
- Background transition: `data-background-transition="none"` on pedagogical slides
- No Pixabay backgrounds in generated output (per skill: all backgrounds use solid colors)
- One consistent worked example per strategy block (no mixing examples)

**JSON** (`output/*/*.json`, `knowledge-base/lesson plan shapes/json/*.json`):
- Underscore keys: `lesson_plan`, `answer_key` (not hyphenated `answer-key`)
- Required fields: `teacher`, `lesson_plan` with `stages[]`
- Each stage has: `stage_number`, `stage`, `stage_aim`, `procedure`, `time`, `interaction`
- Answer key format: `"none"` or valid path string

**Python** (`scripts/*.py`):
- Language quality transforms: `humanize_stage_aim` bans template patterns
- Date format: `ddmmyy` → "D Month, YYYY"
- Minute indicators stripped from procedure: `"3 min."` removed
- Answer key: markdown → Typst markup transclusion
- Windows paths: `\` → `/` for Typst
- No deprecated `json_to_markdown.py` for new presentations
- No new `data-markdown` usage (markdown pipeline permanently abandoned)

**Typst** (`.typ` files, `build_typ_content()` generated content):
- Font: Roboto OTF from TinyTeX path via `--font-path`
- Leading: `#set par(leading: 0.55em)` (additional space, not multiplier)
- Top margin: 1.25in (prevents logo clipping on print)
- Logos: page 1 only via `context { if counter(page).get().first() == 1 { ... } }`
- Logo files: `templates/Image_20260324_141022.png` (ACT), `templates/cambridge.png` (Cambridge)
- Content transforms applied: date humanized, stage aims humanized, procedure cleaned, answer key transcluded

**Language Quality** (any text content):
- Stage aims: natural English, NOT template fills
- Banned patterns: "To lead-in to...", "To reading for gist", "To post-reading speaking task"
- Acceptable patterns: "To activate interest in...", "To get the general idea of...", "To discuss ideas from..."
- Icon describes function of slide, not topic

**General Code Quality**:
- No unused imports
- No hardcoded secrets or tokens
- No hallucinated dependencies (check imports against known project deps: pillow, requests, typst CLI)
- No commented-out dead code without clear purpose
- Error handling present for external tool calls (typst, subprocess)

**Phase 4 — Summary**
8. Report: total files changed, tests pass/fail, lint issues found, quality rule violations
9. If all clear: "✅ Review passed"
10. If violations found: list each violation with file path and explanation
